# 已知问题与下一步

以下是代码审查及已有验收的实际边界，不代表这些问题都已复现成数据丢失。

## 优先修复

1. **系统菜单的导入导出保存队列**：`electron/main.ts` 中系统菜单/托盘入口只 flush 窗口几何，没有显式等待各渲染器的最后编辑队列。快速输入后立即用系统菜单导出，可能导出前一快照。暂时使用便签内部“更多”面板的导入导出，并确认已保存；该入口等待保存队列。下一步为共享 flush 协调和立即导出回归测试。
2. **大笔记库保存延迟**：当前同步验证及重写整份 JSON，并保留上一有效版本。大型笔记库可能增加主进程延迟。下一步先测量真实合成大数据，再设计保留退出 flush 的保存合并。
3. **设备覆盖**：Windows 与 Intel Mac 的安装/卸载、中文输入法、多屏、缩放和登录启动还缺实机验收。构建成功不能替代这些检查。
4. **构建工具链弃用提示**：安装时有 inflight、旧 glob/rimraf 等传递开发依赖的弃用提示。2026-10-26 的官方审计为零已知漏洞，该历史结果不代表这些包仍被维护；当前审计结果见下一项。应随 Electron Builder 等上游更新跟踪传递依赖。
5. **2026-11-03 开发依赖审计**：当前锁文件仍报告 15 条中等级别依赖记录，均来自开发/打包工具链对 `minimatch` 的依赖传播，对应同一份 [GHSA-g3hv-75wg-m249 公告](https://github.com/advisories/GHSA-g3hv-75wg-m249)，不是 15 个独立根因。修复版为 11.0.1，现有父包分别要求 3／5／9／10 代；跨主版本更新需要上游兼容性与打包验证。CI 保持 `npm audit --audit-level=high` 门槛，跟踪上游可兼容的更新。此前审计为零的记录仅代表当时的公告库结果。

本轮已将仅由开发工具 `wait-on` 引入的 `follow-redirects` 升至 1.16.2、`joi` 升至 18.3.1，分别处理 [重定向敏感头公告](https://github.com/advisories/GHSA-mrwp-f3q8-3g9p) 和 [邮件校验性能公告](https://github.com/advisories/GHSA-4528-x5fx-h6hg)。2026-11-03 的官方 registry 审计为 0 critical、0 high、15 moderate；常规便签运行依赖版本未改变。

## 产品边界

- 没有云同步、协作、时间提醒、图片附件、搜索分类、完整历史版本或移动端。
- 没有正式发行签名、公证和自动更新源；Linux 尚无发行目标。
- AI 整理后的新正文是纯文本，需要核对语义；撤销恢复原始格式。
- 默认字色与背景的可读性检查不保证任意粘贴文字色都达标。
- 单个整包备份限制 50 MB。损坏或不支持的新数据版本会保留原件并拒绝覆写，而非自动修复。

## 维护路线

先解决保存队列边界并补齐真实设备证据；随后根据实际 Issue 反馈安排待办勾选、便签搜索与分类、误删恢复和历史版本。提醒、图片与同步需另行设计数据及隐私边界，没有承诺交付日期。
